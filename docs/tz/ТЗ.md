# ТЗ: TeleFolders v1

## 1. Продукт

**TeleFolders** — веб-приложение для управления чатами Telegram. Пользователь входит в свой аккаунт (user-сессия, не бот) и получает матрицу «все чаты × все папки»: одним кликом раскладывает чаты, каналы, группы и ботов по папкам, закрепляет, исключает, настраивает флаги папок, архивирует. Плюс новое — удаление чатов, выход из групп и каналов, блокировка, массовые операции.

Ценность: в официальном клиенте раскладка N чатов по M папкам — это N×M переходов по меню. Здесь — одна таблица и один клик по ячейке.

**Форм-фактор — чисто веб.** Десктоп-сборки (исполняемые файлы, pip-пакет, окно Eel) не поддерживаются, Python-код удаляется целиком.

**Вне рамок v1:** чтение/отправка сообщений, несколько аккаунтов одновременно, серверный бэкенд с пользовательскими данными, нативные приложения, папки-ссылки (`chatlist.*`).

### Глоссарий

| Термин                     | Значение                                                                                                                                      |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Диалог                     | Запись в списке чатов: личка, группа, супергруппа, канал, бот, «Избранное»                                                                    |
| Пир                        | Сущность Telegram: `User`, `Chat`, `Channel`                                                                                                  |
| Папка                      | `DialogFilter`: id, title, emoticon, 8 флагов и три списка пиров                                                                              |
| include / exclude / pinned | Три отношения чата к папке                                                                                                                    |
| Флаги папки                | `contacts`, `nonContacts`, `groups`, `broadcasts`, `bots` (включить категорию) и `excludeMuted`, `excludeRead`, `excludeArchived` (исключить) |
| Архив                      | Служебная папка с id `1` (основной список — `0`)                                                                                              |
| Матрица                    | Главный экран: строки — чаты и флаги, колонки — папки                                                                                         |

### Где выполняется MTProto

**В браузере пользователя.** `@mtcute/web`, WebSocket-транспорт, сессия в IndexedDB (`IdbStorage`). Сервер отдаёт только статику/SSR-оболочку и **никогда** не видит ни сессию, ни телефон, ни код, ни 2FA-пароль.

Следствия:

- Telegram-слой — client-only: никаких вызовов в серверных loader'ах, вызов из SSR должен бросать понятную ошибку разработчику;
- `api_id`/`api_hash` попадают в клиентский бандл — нужно решение (см. §7);
- сессия живёт в IndexedDB конкретного браузера, очистка данных сайта = повторный вход.

### Структура

```
src/

  telegram/          ЕДИНСТВЕННОЕ место, где импортируется mtcute
    client.ts        singleton TelegramClient, IdbStorage
```

### Доменные типы

```ts
export type PeerKind =
  'user' | 'bot' | 'group' | 'supergroup' | 'channel' | 'saved'

export type Chat = {
  id: number // маркированный id диалога
  peerId: number // сырой id сущности
  kind: PeerKind
  title: string
  username?: string
  photoUrl?: string // ленивая загрузка, blob-url
  isPinned: boolean // глобальный пин
  isArchived: boolean
  isMuted: boolean
  unreadCount: number
  isSelf: boolean // «Избранное»
  canDelete: boolean
  canLeave: boolean
  canBlock: boolean
  isOwner: boolean // я создатель группы/канала — предупреждение при выходе (F5.4)
  folders: Record<number, 'include' | 'exclude' | 'pinned'>
}

export type BlockedPeer = {
  id: number
  kind: PeerKind
  title: string
  username?: string
}

export type FolderFlag =
  | 'contacts'
  | 'nonContacts'
  | 'groups'
  | 'broadcasts'
  | 'bots'
  | 'excludeMuted'
  | 'excludeRead'
  | 'excludeArchived'

export type Folder = {
  id: number
  title: string
  emoticon?: string
  flags: Record<FolderFlag, boolean>
  includeCount: number // для правила «папка не может быть пустой»; union include+pinned, не сумма — пиннед-пир не дублируется в include (см. §3.3)
}
```

`PeerRef` — единый адаптер `{ id, kind }` (без отдельного `accessHash`: `id` — маркированный id диалога, mtcute сам резолвит access hash по нему через свой кэш пиров). Сопоставление диалог↔папка делать по маркированному id (`getMarkedPeerId`), а не по паре id+kind: он совпадает с тем, что хранится в `includePeers`/`pinnedPeers`/`excludePeers` фильтра.

Колонка «Архив» — псевдо-папка с id `1`: рендерится колонкой, но пишется не через `updateDialogFilter`, а через API архивации.

### Кэш и синхронизация

- Два основных query: `['folders']`, `['dialogs']`, большой `staleTime` (10 минут у `dialogs` — полный `iterDialogs` дорог на большом аккаунте).
- Все мутации оптимистические: `onMutate` патчит кэш точечно (только затронутое поле чата/папки, не весь список — иначе откат одной мутации стирает результат другой, выполнившейся параллельно), `onError` откатывает именно этот патч + тост. Для `setChatRelation`/`setFolderFlag` `onSuccess` пишет в кэш папку, которую вернул сервер, вместо `invalidateQueries` — сервер уже вернул актуальный результат read-modify-write, второй запрос не нужен; `dialogs` при этом не трогается вовсе, так как мутации не меняют ничего в нём, кроме уже применённого оптимистичного патча.
- Индикатор «идёт запись» на конкретной ячейке/флаге строится через `useMutationState` по `mutationKey`, а не `.isPending` одного `useMutation()` — иначе виден только последний из нескольких одновременно нажатых.
- Кнопка «Обновить» — принудительный `invalidateQueries`.
- Подписка на апдейты Telegram (изменения из официального клиента приезжают сами) — улучшение последнего этапа, не обязательна.

## 3. Слой Telegram: контракт

Названия методов mtcute сверять с актуальной версией пакета — здесь важна семантика.

### Авторизация

| Функция                     | Контракт                                                  | Обязательные ошибки                                                   |
| --------------------------- | --------------------------------------------------------- | --------------------------------------------------------------------- |
| `getAuthState()`            | `'unauthorized' \| 'authorized'` + профиль                | —                                                                     |
| `sendCode(phone)`           | `phoneCodeHash`, способ доставки                          | `PHONE_NUMBER_INVALID`, `PHONE_NUMBER_BANNED`, `FLOOD_WAIT`           |
| `signIn(phone, hash, code)` | `{ status: 'ok', user } \| { status: 'password_needed' }` | `PHONE_CODE_INVALID`, `PHONE_CODE_EXPIRED`, `SESSION_PASSWORD_NEEDED` |
| `checkPassword(password)`   | `{ user }`                                                | `PASSWORD_HASH_INVALID`                                               |
| `resendCode()`              | новый код другим способом                                 | `FLOOD_WAIT`                                                          |
| `logOut()`                  | завершает сессию **и чистит IndexedDB и кэш Query**       | —                                                                     |
| `getMe()`                   | `{ id, username, firstName, lastName, photoUrl }`         | —                                                                     |

### Папки

```ts
listFolders(): Promise<Folder[]>
createFolder({ title, emoticon?, includePeers }): Promise<Folder>
renameFolder(id, title, emoticon?): Promise<void>
deleteFolder(id): Promise<void>
reorderFolders(ids: number[]): Promise<void>
setFolderFlag(id, flag, value): Promise<void>
setChatRelation(id, peer, relation: ChatFolderRelation | null): Promise<void>
```

Обязательные правила:

1. **Read-modify-write.** `updateDialogFilter` перезаписывает фильтр целиком: всегда сначала получить актуальный фильтр, изменить, записать. Нельзя строить фильтр из данных UI-кэша.
2. **Взаимоисключение отношений.** Пир ровно в одном из трёх списков; при установке нового удаляется из остальных.
3. **`pinned` подразумевает включение** — маппинг отдаёт такой пир как `pinned`, а не одновременно `include`.
4. **Папка не может быть пустой.** `FILTER_INCLUDE_EMPTY` → `FOLDER_MUST_NOT_BE_EMPTY` → «Папка не может быть пустой». Плюс UI заранее дизейблит действие, которое опустошит папку (`includeCount === 1`) — кроме случая, когда у папки включён хотя бы один флаг-категория (`contacts`/`groups`/…): тогда неизвестно без запроса к серверу, останется ли она пустой, поэтому дизейбл не ставится.
5. **Служебные фильтры** (`DialogFilterDefault`, чатлисты) не редактируются — read-only.
6. **Лимиты.** При `FILTERS_TOO_MUCH` / `*_TOO_MUCH` — понятное сообщение с упоминанием Premium, а не «Произошла ошибка».
7. **Очередь записи.** Не более одной записи в один фильтр одновременно, иначе изменения теряются.

### Диалоги

```ts
listDialogs(): Promise<Chat[]>                    // основной список + архив, с прогрессом
getChatPhoto(chat): Promise<string | undefined>   // ленивая догрузка, blob-url, кэш
```

`canDelete` / `canLeave` / `canBlock` вычисляются в маппере: личка и бот → удаление диалога и блокировка; группа/канал, где я не создатель → выход; где создатель → выход с предупреждением; «Избранное» → только очистка истории.

### Действия над чатами

```ts
setArchived(peer, archived)        // folders.editPeerFolders (0/1)
setPinned(peer, pinned)            // messages.toggleDialogPin
setMuted(peer, muted)
markRead(peer)
deleteChat(peer, { revoke? })
leaveChat(peer, { deleteFromList? })
blockUser(peer) / unblockUser(peer)
listBlocked(): Promise<BlockedPeer[]> // не Chat: заблокированного может не быть в диалогах
```

Семантика «удаления» различается по типу пира — реализовать точно, действия необратимы:

| Тип чата                     | Что происходит                                                                                                                                                    |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Личка                        | удалить историю у себя; опция «удалить и у собеседника» (`revoke`), если Telegram позволяет                                                                       |
| Бот                          | остановить и удалить; опция «заблокировать»                                                                                                                       |
| Группа / супергруппа         | выйти (+ убрать из списка); владелец обычной группы — предупредить, что чат останется; владельцу супергруппы Telegram выйти не даёт (`USER_CREATOR`) — пункта нет |
| Канал (подписчик)            | отписаться                                                                                                                                                        |
| Канал/группа, где я владелец | удаление всего канала — отдельное действие с вводом названия для подтверждения, **по умолчанию выключено**                                                        |
| Избранное                    | только очистка истории                                                                                                                                            |

### Ошибки

```ts
type AppError = {
  code:
    | 'FOLDER_MUST_NOT_BE_EMPTY'
    | 'FLOOD_WAIT'
    | 'LIMIT_REACHED'
    | 'AUTH_REQUIRED'
    | 'NETWORK'
    | 'PERMISSION_DENIED'
    | 'UNKNOWN'
  retryAfterSec?: number
  raw: string // исходный текст RPC-ошибки, сохраняем всегда
}
```

`FLOOD_WAIT` — прозрачное ожидание и один автоповтор; при `retryAfterSec > 60` показать пользователю таймер. `AUTH_REQUIRED` (`AUTH_KEY_UNREGISTERED`, `SESSION_REVOKED`) → сброс сессии и редирект на `/login`.

## 4. Функционал

Приоритеты: **P0** — без этого релиза нет, **P1** — заявленное новое и закрытие долгов, **P2** — расширение.

### F1. Авторизация — P0

- **F1.1** Три шага: телефон (выбор страны, маска) → код → 2FA-пароль. Валидация TanStack Form + Zod.
- **F1.2** Понятные ошибки: неверный номер, неверный код, истёкший код, неверный пароль, флуд с таймером.
- **F1.3** «Отправить код ещё раз», «Изменить номер».
- **F1.4** Сессия переживает перезагрузку, автовосстановление без повторного ввода.
- **F1.5** Выход: завершение сессии, очистка IndexedDB и кэша Query, редирект на `/login`.
- **F1.6** Дисклеймер: неофициальный клиент, работает напрямую из браузера, данные никуда не отправляются.

### F2. Матрица — P0

- **F2.1** Колонки: `Чат | Архив | папка 1 … папка N | + Папка`. Первая колонка и шапка залипающие.
- **F2.2** 8 строк флагов папок вверху таблицы, визуально отделены, клик переключает флаг.
- **F2.3** Ячейка чат×папка — циклическое переключение `нет → включён → закреплён → исключён → нет`.
- **F2.4** Колонка «Архив» — тумблер архивации.
- **F2.5** Свой чат подписан «Избранное».
- **F2.6** Оптимистичный апдейт, откат при ошибке, тост.
- **F2.7** «Папка не может быть пустой» + превентивный дизейбл последнего include-пира.
- **F2.8** Виртуализация: 2000 чатов × 20 папок скроллятся плавно.
- **F2.9** Кнопка «Обновить».
- **F2.10** Скелетоны и прогресс «загружено N чатов».
- **F2.11** Пустые состояния: нет папок, нет чатов, ничего не найдено.

### F3. Поиск, фильтры, сортировка — P1

- **F3.1** Поиск по названию и `@username`, клиентский, мгновенный.
- **F3.2** Фильтры по типу (личные, группы, каналы, боты) и состоянию (архивные, без уведомлений, непрочитанные, «не входит ни в одну папку»).
- **F3.3** Тумблер «Показывать архивные», состояние сохраняется.
- **F3.4** Сортировка: порядок Telegram (по умолчанию), название, число папок, непрочитанные.
- **F3.5** Состояние фильтров в URL (search params роутера).

### F4. Управление папками — P1

- **F4.1** Создание: название, эмодзи, начальный набор чатов, учёт лимита.
- **F4.2** Переименование и смена иконки.
- **F4.3** Удаление с подтверждением.
- **F4.4** Порядок папок drag-n-drop колонок → `updateDialogFiltersOrder`.
- **F4.5** Счётчики в шапке колонки: включено / исключено / закреплено.
- **F4.6** Служебные фильтры и чатлисты — read-only со значком.

### F5. Удаление, выход, блокировка — P1 (новое)

- **F5.1** Контекстное меню строки: Закрепить, В архив, Уведомления, Отметить прочитанным, Открыть в Telegram, Удалить, Выйти, Заблокировать.
- **F5.2** Глобальное закрепление чата (`setPinned`), с учётом лимита закреплённых.
- **F5.3** Удаление чата: диалог подтверждения показывает название, что именно произойдёт (по таблице §3), для лички — чекбокс «удалить также у собеседника». Подтверждение обязательно, «не спрашивать больше» не предусмотрено.
- **F5.4** Выход из группы/канала с подтверждением, отдельное предупреждение для владельца. Владельцу канала/супергруппы выход не предлагается: `channels.leaveChannel` отвечает `USER_CREATOR`.
- **F5.5** Блокировка и разблокировка + раздел «Заблокированные». Статус блокировки берётся из `contacts.getBlocked` (в диалогах его нет): в меню заблокированного — «Разблокировать» вместо «Заблокировать».
- **F5.6** «Пожаловаться на спам» вместе с блокировкой — P2.
- **F5.7** Все деструктивные действия дают тост с итогом.
- **F5.8** Удаление своего канала/группы по умолчанию недоступно; включается флагом фичи, требует ввода названия чата. В v1 флаг не заведён — действия нет вовсе.

### F6. Массовые операции — P1 (новое)

- **F6.1** Чекбоксы строк, `Shift`-диапазон, «выбрать всё по текущему фильтру», счётчик.
- **F6.2** Панель действий: добавить/исключить/снять отношение к папке, архивировать, mute, отметить прочитанными, покинуть, удалить, заблокировать.
- **F6.3** Последовательная очередь с прогрессом («12 из 40»), отменой оставшихся и отчётом: сколько успешно, сколько с ошибкой и почему. При `FLOOD_WAIT` — пауза и продолжение, не падение.
- **F6.4** Деструктивные массовые действия — отдельное подтверждение со списком затронутых чатов (первые 10 + «и ещё N»).
- **F6.5** Массовое добавление в папку — **одной** записью фильтра, не N записями.
- **F6.6** Уточнения реализации: выделение хранится по id и переживает смену фильтра, но действие применяется только к выделенным **видимым** чатам. Чаты, к которым действие неприменимо (выйти из лички, заглушить заглушённый, удалить «Избранное»), пропускаются заранее и учитываются в отчёте как «пропущено»; в меню у каждого действия виден счётчик применимых чатов. Массовое удаление лички — только у себя (без `revoke`). Архивация — тоже одним запросом (`folders.editPeerFolders` принимает список). После отчёта выделенными остаются только чаты с ошибкой — для повтора.

### F7. Карточка чата — P0

- **F7.1** Аватар, название, `@username`, тип, непрочитанные, статусы архива/пина/уведомлений.
- **F7.2** Полный набор действий F5 и переключатели отношений ко всем папкам.
- **F7.3** Навигация «предыдущий/следующий чат» с учётом фильтров и сортировки, клавиши `←`/`→`, `Esc`.

### F8. Настройки и оболочка — P1

- **F8.1** Переключатель языка (ru/en), ни одной захардкоженной строки.
- **F8.2** Тёмная/светлая тема + системная.
- **F8.3** Профиль в шапке: аватар, имя, `@username`, меню (настройки, обновить, заблокированные, выход).

| Состояние  | Иконка              | Тултип                        | Клик ведёт в |
| ---------- | ------------------- | ----------------------------- | ------------ |
| `none`     | контурный плюс      | «Не входит в папку»           | `include`    |

| `pinned`   | булавка             | «Закреплён в папке»           | `exclude`    |

Цвет — не единственный носитель информации: состояния различимы по форме иконки.

### Взаимодействие

Клик — следующий шаг цикла; `Shift+клик` — сразу `exclude`; правый клик/долгое нажатие — прямой выбор состояния. Клавиатура: стрелки по ячейкам, `Space`/`Enter` — переключение, `Esc` — снять выделение; матрица полностью управляема с клавиатуры (ARIA grid).

### Копирайтинг и i18n

Все строки через Paraglide, ключи вида `matrix_cell_include`, `error_folder_empty`, `confirm_delete_chat_title`. Плюрализация обязательна. Тексты деструктивных подтверждений прямые: «Вы выйдете из группы «X». История переписки будет удалена из вашего списка. Действие необратимо».

### Доступность и адаптивность

`aria-label` на всех иконках-кнопках, фокус-ловушка в модалках и возврат фокуса, `prefers-reduced-motion`, контраст не ниже WCAG AA, прогон addon-a11y на каждый компонент. Десктоп — полная матрица; планшет — горизонтальный скролл с залипающей первой колонкой; мобильный — список чатов, работа с папками через карточку чата.

### Storybook

Обязательные стори: ячейка во всех состояниях, строка флага, шапка колонки папки, строка чата, панель массовых действий, карточка чата, диалоги подтверждения удаления/выхода/блокировки, шаги логина, пустые состояния и ошибки. Данные — из мока `telegram/`, не из сети.

## 6. Нефункциональные требования

**Браузеры:** последние две версии Chrome, Firefox, Safari, Edge. Нужны WebSocket, IndexedDB, WebCrypto.

**Приватность и безопасность**

1. Телефон, код, 2FA-пароль, session string никогда не покидают браузер — ни в запросах к нашему серверу, ни в логах, ни в аналитике.
2. Сессия в IndexedDB, при выходе база удаляется полностью.
3. Никакой аналитики с пользовательским контентом; сбор ошибок — только с согласия и без названий чатов, id и телефона.
4. В консоль не пишутся списки чатов и ответы API. Отладочный вывод — только за флагом разработки.
5. CSP разрешает WSS к серверам Telegram и запрещает сторонние скрипты.
6. Деструктивные операции — всегда через явное подтверждение.

**Производительность**

| Метрика                               | Цель                                          |
| ------------------------------------- | --------------------------------------------- |
| Первая отрисовка оболочки             | < 1.5 с                                       |
| Матрица 2000 чатов × 20 папок         | ≥ 50 fps при скролле                          |
| Реакция ячейки на клик (оптимистично) | < 50 мс                                       |
| Загрузка списка диалогов              | прогресс с первых чатов, экран не блокируется |

**Качество:** TS strict без `any` в доменных слоях; `pnpm lint`, `pnpm check`, `tsc --noEmit` зелёные в CI; `routeTree.gen.ts` и `src/paraglide/**` не редактируются руками; импорты через алиас `#/*`; компонент готов только со стори.

**Тесты**

| Уровень                           | Что покрываем                                                                                              |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Unit (Vitest)                     | мапперы, правила отношений чат/папка, нормализация ошибок, очередь мутаций                                 |
| Компонентные (Storybook + vitest) | ячейка, строка флага, панель массовых действий, диалоги подтверждения, шаги логина                         |
| Интеграционные                    | на моке `telegram/`: раскладка по папкам, массовое добавление, удаление с подтверждением, откат при ошибке |
| Ручные                            | аккаунт с ≥ 5 папками и ≥ 300 чатов перед релизом                                                          |

Обязательные кейсы: пустая папка, `FLOOD_WAIT` в середине массовой операции, отвал авторизации, чат в нескольких папках, «Избранное», архивный чат при выключенном показе архива.

**CI:** `install → lint → prettier → tsc → vitest → build → build-storybook`, красный пайплайн блокирует мёрж.

## 7. Решения, которых не хватает

1. **`api_id` / `api_hash`** — вшить свои в бандл (удобно, но общие лимиты и риск бана приложения на всех) или просить пользователя завести свои на my.telegram.org (безопаснее, но выше порог входа)? Компромисс: вшитые по умолчанию + возможность подставить свои в настройках. Нужно до этапа 1.
2. **Хостинг — решено: GitHub Pages.** Это статический хостинг без сервера — TanStack Start в текущей конфигурации (`src/server.ts`, SSR-рендер в `RootDocument`) на нём не работает как есть. До деплоя нужно на выбор: (а) собрать приложение как чистую SPA (`tanstackStart({ prerender: ... })`/статический экспорт без серверного окружения — проверить актуальный способ в доке TanStack Start) и обслуживать `index.html` на все пути через `404.html`-фоллбэк (стандартный трюк для SPA на GH Pages), либо (б) вынести конкретно на GH Pages только билд, а серверная часть (если останется нужна) — на отдельный хостинг. Раз MTProto и так работает целиком в браузере (§2), серверу в проде почти нечего делать — вариант (а) выглядит естественным, но требует отдельной задачи: пройтись по `vite.config.ts`/`router.tsx` на предмет SSR-специфичного кода, проверить `base` path (репозиторий на GH Pages обычно живёт не в корне домена — `/<repo>/`), и убедиться, что клиентский роутинг (TanStack Router) переживает прямые заходы на `/matrix`, `/en/login` и т.д. без сервера.
3. **Браузерный MTProto** — на этапе 1 экспериментально подтвердить, что WebSocket-транспорт mtcute стабилен во всех целевых браузерах и прокси не нужен. Если нужен — ломается вся браузерная топология из §2.
4. **Судьба ветки `main`** — оставить как legacy с пометкой в README или убрать Python-код после релиза v1?
5. **Дизайн** — есть ли макеты? Если нет, интерфейс строится на shadcn-примитивах по §5.
